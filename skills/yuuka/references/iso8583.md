# ISO 8583 payment gateway ledger sheet

A domain sheet: open it alongside the language sheet when code frames, parses,
packs, routes or matches ISO 8583 card messages (authorization, financial,
reversal, network management). The ledger rungs are the same; this sheet says
what they mean for a payment switch. Tested, benchmarked JS demo:
[`examples/js/iso8583.js`](../../../examples/js/iso8583.js).

## When this sheet applies

- A TCP listener or client speaking ISO 8583 to an acquirer, issuer, card network or terminal fleet.
- Message codecs: MTI, bitmaps, fixed / LLVAR / LLLVAR data elements (DEs).
- Request/response matching, timeout reversals, STAN/RRN bookkeeping, echo/sign-on (0800).

The wire format is **dialect data**, not code. Each network or host publishes its own spec: header style, field encodings (ASCII, BCD, EBCDIC, binary), which DEs exist, and their max lengths. Encode it as a table and never hard-code it into branches.

| Piece | Common forms | Notes |
|---|---|---|
| Length header | 2-byte big-endian binary; 4 ASCII digits; sometimes a 5-byte TPDU after it | The first untrusted length you read. |
| MTI | 4 digits: version · class · function · origin (`0200` = 1987 financial request) | ASCII (4 B) or BCD (2 B). |
| Bitmap | 8 B primary; bit 1 set ⇒ 8 B secondary (DE65–128) | Binary, or 16 hex chars. Bit *k* is MSB-first: byte `(k-1)>>3`, mask `0x80 >> ((k-1)&7)`. |
| Fixed DE | `n6` (DE3), `n12` (DE4), `an2` (DE39), `b8` (DE64 MAC) | Length comes from the spec, not the wire. |
| LLVAR / LLLVAR | DE2 PAN `n..19`, DE35 track 2 `z..37`, DE55 ICC `b..255`/`..999` | 2- or 3-digit length prefix, then the bytes. Untrusted again. |

## Goal & tests

**Goal.** Derive it from throughput, not vibes. `TPS × ns/op = CPU share`, so 2,000 TPS × 5 µs/parse is 1% of one core. State the per-message budget at a production-shaped frame, for example `goal: parse 0200 (~350 B, DE55 180 B) ≤ 1 µs · 0 allocs after warm-up; pack 0210 ≤ 1 alloc (the output)`. Network round trips are tens of ms, so a codec that is already under 1% CPU is a cold path: say so and stop.

**Tests first**, one table-driven suite per dialect:

- **Golden vectors**: hex dumps from the network's certification spec or a scrubbed capture, parsed and re-packed byte-for-byte. Include one with a secondary bitmap.
- **Empty / header-only / truncated** frames refused with a typed error, never an out-of-bounds read.
- **Exactly at capacity**: each LLVAR/LLLVAR at its max (DE2 = 19, DE35 = 37, DE55 = max) passes. **Overflow**: max + 1 is refused on parse *and* on pack.
- **Bitmap**: a bit set for a DE the dialect doesn't define → `UNKNOWN_FIELD`. Bit 1 set with no secondary bytes → `TRUNCATED`. Trailing bytes after the last DE → `TRAILING`.
- **Digits**: non-digit in an `n` field, MTI, or length prefix → `BAD_DIGIT`.
- **Money**: DE4 at `000000000000` and `999999999999` decodes exactly as an integer.
- **Reuse**: a reused message object carries no stale DEs from the previous frame, and none after a failed parse.
- **Budget**: alloc assert per message (`testing.AllocsPerRun`, JMH `gc.alloc.rate.norm`, `GC.GetAllocatedBytesForCurrentThread`, dhat). Where there's no alloc counter, prove structure: a view shares the frame's backing store, and the output has no slack.
- **Fixtures use test cards only** (e.g. `4111111111111111`). Real PANs never enter a repo.

## Size & frame caps

| Size known… | Use |
|---|---|
| at compile time: max frame for the dialect | Fixed per-connection read buffer `[maxBody]byte` / `new byte[MAX]`. Caps the untrusted header for free. |
| at compile time: the field table | `[129]FieldSpec` (or `[193]` with a tertiary bitmap) indexed by DE number. |
| per message: parsed fields | Two fixed arrays `off[129]`, `len[129]` (`uint16`: offsets < max frame) plus the bitmap. No map. |
| before writing: outgoing frame | Sum the spec in pass 1 (MTI + bitmap(s) + Σ prefix + len), then one exact allocation or one `Grow`, written in pass 2. |
| in flight: request/response matching | Map pre-sized to the in-flight cap: `make(map[Key]*Pending, maxInFlight)`. |

Read loop, Go:

```go
var hdr [2]byte
if _, err := io.ReadFull(r, hdr[:]); err != nil { return err }
n := int(binary.BigEndian.Uint16(hdr[:]))
if n < minBody || n > maxBody { return errBadFrame } // yuuka: cap from dialect spec §x
body := c.buf[:n]                                      // c.buf is [maxBody]byte, reused per frame
if _, err := io.ReadFull(r, body); err != nil { return err }
```

Netty: `new LengthFieldBasedFrameDecoder(MAX_BODY, 0, 2, 0, 2)`. Tokio: `LengthDelimitedCodec::builder().length_field_length(2).max_frame_length(MAX_BODY)`. In both, the max is the cap. Never leave it at the library default.

## Letter vs number

- **MTI** → `uint16` (0–9999) parsed once, or a `switch` on its 4 bytes. Never route on a `string` built per message.
- **DE numbers** → small ints indexing arrays. Never `"DE4"` / `"4"` string keys.
- **Bitmap** → `[16]byte` or two `uint64`. Never a `"0101…"` bit string or a hex string.
- **Amount (DE4)** → `int64` **minor units**, decoded straight from the digits. `n12` ≤ 999,999,999,999 fits `int64` (and is exact in a JS number, < 2⁵³). The currency exponent comes from DE49 (ISO 4217 numeric: JPY 0, USD/THB 2, KWD 3). **Never float, never `ParseFloat(x)/100`.**
- **STAN (DE11)** → `uint32` (n6). **Response code (DE39)** → `[2]byte` compared bytewise, or mapped to an enum once.
- **Text DEs** (DE37 RRN, DE41 TID, DE42 MID) → byte views. Decode to a string only on cold paths (logs, admin APIs).
- **PAN, track 2, PIN block (DE2/35/52)** → bytes you can zero. In GC languages, strings are immutable and can't be wiped, so never turn sensitive DEs into strings.
- **BCD dialects**: two digits per byte. Odd lengths get one pad nibble; which side, and `0` or `F`, is dialect data and goes in the spec table.

## Pre-allocate & reuse

- **One message struct per connection**, refilled per frame (`msg.reset()` clears the bitmap; offsets are overwritten). On busy servers, `sync.Pool`, Netty's pooled `ByteBuf`, `ArrayPool<byte>`.
- **Parse = zero copies.** Fields are `(offset, len)` into the frame. A view (`body[o:o+n]`, `ByteBuffer.slice`, `ReadOnlySpan<byte>`, `&[u8]`) is materialised only when read.
- **Pack = one allocation (the output), or zero into a reused buffer**, and only if the write path copies before returning. Go's `conn.Write` returns after the bytes are handed to the kernel, so reusing after return is safe. Node's `socket.write` keeps a reference, so allocate fresh per frame. That is exactly what the JS demo measured and kept.
- **Echoed DEs** (3, 4, 7, 11, 12, 13, 37, 41, 42, 49 in a 0210) are written straight from request views into the response buffer. No intermediate copies.
- **Digits out**: write the number backwards into the output bytes. Never `fmt.Sprintf("%012d")` / `String.format` / `padStart` per field on the hot path.

## Length checks

- **Header first**: `minBody ≤ n ≤ maxBody` before reading or allocating anything. Then `header == bytes received`.
- **Every DE read** is guarded: `if p+n > end { return errTruncated }`. Prefix digits are validated (0–9), then `len ≤ spec.max`, then `len ≤ remaining`, in that order.
- **Secondary bitmap**: check bit 1 and that 8 more bytes exist before reading DE65+.
- **Unknown bit set** → reject. The parser can't know the field's length, so skipping it would desync every later field.
- **After the last DE**: `p == end`, or reject trailing bytes.
- **Failed parse clears the message.** Half-filled offsets must never be readable.
- **Hoist** `end := len(frame)` and the spec lookup. One bounds proof per field, not per byte: slice once (`v := frame[p : p+n : p+n]` in Go, `&frame[p..p+n]` in Rust) and index `v`.

## Pass by role

| Role | Signature (Go · Rust · C# · Java) |
|---|---|
| frame, read-only | `Parse(frame []byte, m *Msg) error` · `fn parse(frame: &[u8], m: &mut Msg)` · `Parse(ReadOnlySpan<byte> frame, ref Msg m)` · `parse(ByteBuffer frame /* read-only */, Msg m)` |
| message, filled in place | `*Msg` · `&mut Msg` · `ref Msg` · reused `Msg` instance |
| field read | returns a view into the frame, valid until the buffer is reused |
| field that **outlives the frame** (STAN, RRN, TID for reversal/late-response matching) | copied once into a fixed array `[12]byte` / `[u8; 12]` owned by the pending entry |
| match key | small value struct `{stan uint32; tid [8]byte; ts uint64}`. Never a concatenated string. |
| response packing | `Pack(dst []byte, m *Resp) ([]byte, error)`: append into the caller's buffer, return it |

## Benchmarks

- Production mix, not one toy message: mostly 0200/0210 with realistic DE55 sizes, plus 0800 echo and some 0400 reversals.
- Report **ns/op, B/op, allocs/op per message** for parse and pack separately (`go test -bench . -benchmem`, JMH with `-prof gc`, BenchmarkDotNet `[MemoryDiagnoser]`, criterion).
- Compare against the goal derived from TPS. If parse is already < 1% of a core, the codec isn't the bottleneck: measure the gateway end to end before touching it.
- Run the golden-vector suite on every change. A faster codec that mis-frames one field is a financial incident.

## Copy-and-destroy anti-patterns

| Anti-pattern | Fix |
|---|---|
| whole frame → `string` / hex string, then `substring` per DE | Parse the bytes; offsets + views |
| bitmap → `"0101…"` string, `parseInt` per chunk | Bit test on bytes: `bm[(k-1)>>3] & (0x80 >> ((k-1)&7))` |
| `map[string]string` / `Map<String,String>` keyed `"DE4"` | `[129]` offsets/lengths indexed by DE number |
| `ParseFloat(de4) / 100` | Integer minor units from the digits + DE49 exponent |
| `fmt.Sprintf("%012d", amt)` / `padStart` per field when packing | Write digits backwards into the reserved bytes |
| `s += prefix + value` building the response | Size in pass 1, one buffer, write in pass 2 |
| `make([]byte, llvarLen)` from the wire before checking `≤ spec.max` | Check the prefix digits, then max, then remaining |
| logging the raw frame or `msg.String()` with DE2/35/52 | Masked PAN (first 6 / last 4), sensitive DEs omitted |
| new message object + new read buffer per frame | One per connection, reset per frame; pooled on busy servers |
| match key `stan + "|" + tid + "|" + ts` | Fixed-size struct key |

## Never cut (payments)

These sit on top of the main never-cut list:

- **Every length from the wire is untrusted**: the frame header and every LL/LLL prefix are capped by the dialect spec before use.
- **Money is integer minor units.** DE4 with DE49's exponent, never float, never a rounding step.
- **Sensitive authentication data is never stored or logged** after authorization: full track (DE35/45), CVV, PIN block (DE52). The PAN is masked to at most first 6 / last 4 in logs. Sensitive DEs live in byte buffers that are zeroed after use, never in strings.
- **Views never outlive the frame.** Anything kept past the read (pending-request entries, reversal records, audit rows) is copied into owned storage first.
- **A timeout is not a decline.** A request with no response gets the dialect's reversal (0400/0420) per the network rules. Never drop it to save a map entry.
- **Golden vectors are never "updated to match"** a faster codec. If the bytes changed, the codec is wrong.
